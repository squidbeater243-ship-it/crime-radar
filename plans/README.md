## Recommended execution order

1. **001** first — everything else that touches easing depends on it existing.
2. **002** and **003** can run in parallel once 001 lands (both depend only on 001; 002 doesn't use `FadeIn`, 003 doesn't touch `UsMap.jsx`'s click handler). Note both 002 and 001 touch `UsMap.jsx` — land 001 first to avoid a merge conflict, even though 002 doesn't functionally depend on 001's change.
3. **004**, **006**, **007**, **008** can each run once their listed dependencies (001 and/or 003) have landed — they don't depend on each other and can run in any order or in parallel.
4. **005** has no dependencies on any other plan in this set — it can run at any point, including first or in parallel with everything else.

A safe fully-sequential order, if running one at a time: **001 → 002 → 003 → 004 → 005 → 006 → 007 → 008**.

## Notes for whoever executes these

- Every plan is self-contained per `improve-animations`' Hard Rule 3 — it
  does not reference "the audit" or "the other plans" for any value, only
  for *ordering* (which plan must land first). Exact values are always
  inlined.
- Every plan's Verification section includes a `prefers-reduced-motion`
  feel-check step. Don't skip it — several of these plans exist
  specifically to close a reduced-motion gap.
- If a plan's "Problem" section code doesn't match what you find in the
  file (drift since commit `e49a344`), its Boundaries section says to
  stop and report rather than improvise — respect that.
